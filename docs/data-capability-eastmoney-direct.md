**实测日期：2026-09-13**
**数据源 ID：`eastmoney-direct`**
**成本：免费，无需密钥**
**证据：`deploy/agentctl-q0/t4-eastmoney-probe.json`**

> 主文档 §6.2 要求 M0 明确区分四态：计划接入 / 凭证已配置 / 测试通过 / 用于正式研究。
> 本卡结论：**测试通过**（行情、身份、日历可取），但**不得进入"用于正式研究"**，
> 原因是它不提供历史时点版本，且没有稳定性承诺。

| 日行情（不复权） | ✅ 可用 | 日期,开,收,高,低,量(手),额(元),振幅,涨跌幅,涨跌额,换手率 | `fqt=0` |

| 交易日历 | ✅ 可推导 | 用上证指数(`1.000001`)日线序列的日期集合 | 无独立日历接口；指数无行情的日期即非交易日 |

## 2. 不能支持什么（这才是重点）

### 2.1 无历史时点（PIT）——决定性限制

实测三条证据（详见证据 JSON 的 `pit.findings`）：

1. **接口没有 as-of / 修订版本参数**。日线返回体只有序列本身，不含 `published_at`、`revision`、`version` 之类的时点元数据。它回答的是"现在看到的历史"，不是"当时看到的值"。
2. **前复权序列会随后续分红变化**。`fqt=1` 以最新除权基准重算历史，因此**同一历史日期的前复权收盘价不是不变量**。这意味着它不能直接作为已发布快照的内容——否则每次分红都会让旧快照"变化"（正是主文档 D06 要防的）。
3. **财务接口只给最新修订版**。可取到 `PUBLISH_DATE`，但无法取得"某次修订当时可见的值"。

**由此产生的硬约束**（主文档 §7.4、§21 风险表首行）：

| 功能 | 结论 |
|---|---|
| 正式历史 PIT 回测 | ❌ **不可启用** |
| 依赖 PIT 财务的因子 F07–F10 | ❌ 默认关闭（`configs` 中 `pit_dependent_factors_enabled: false`） |
| 前向观察 `LIVE_OBSERVED` | ✅ **推荐**：从接入日起自行归档，每次抓取记录 `first_seen_at` 与原始响应哈希 |
| 当前研究展示 | ✅ 可用，但必须标注为"当前研究"，不得称为历史验证 |
| 事件归档与阅读 | ✅ 照常运行（§3.3/§7.4 明确：历史数据不足不删除新闻线） |

### 2.2 限流与稳定性

实测过程中，**约十余次请求后** `push2his.eastmoney.com` 与 `push2.eastmoney.com` 开始
统一以 `RemoteDisconnected` / `连接被对端关闭` 拒绝，且换用不同客户端（PowerShell、
urllib、httpx）与不同子域（`82.push2his`）**均无法恢复**，持续十余分钟未缓解。

这不是代码缺陷，是服务的真实行为。结论：

- **无 SLA、无配额承诺**，主文档 §6.4"首期不承诺免费或固定低价"在此得到证实。
- 抓取器必须内置**指数退避 + 礼貌间隔 + 熔断**，并把"数据源不可用"纳入 A10 降级用例。
- 生产管道不能只依赖单一免费源；需要备选源与可重放的自建归档。

## 5. 对本项目路径的影响

**M0 结论：可以继续，但范围必须收窄到"价格研究 + 前向事件观察"。**

主文档 §19 已预置该情形："M0 验证失败不是项目必须停止：可以收窄到有可靠数据的价格研究
和前向事件观察。但不能在不改标识、不改范围的情况下继续声称具备完整历史因果/收益验证。"

因此：

- ✅ 可做：证券身份、行情、快照、有限模拟账本、S1 价格类基线（F01/F02/F04/F05/F06）、事件归档、研究卡。
- ❌ 不可做：F07–F10（PIT 财务）、历史财务回测、任何声称"历史因果验证"的结论。
- 🔁 **必须从接入第一天就启动前向归档**——这是唯一能逐步获得真实 PIT 数据的途径，
  且越晚开始，缺失的历史越长。
