### 本轮修的是"同一行的一整族写法"

``现金及现金等价物净…额`` 这一行在真实原文里有**五种**写法，随当期增减方向与
披露习惯而变：

```
现金及现金等价物净增加额              实测 000651
现金及现金等价物净减少额              实测 002415 2024H1（当期净减少）
现金及现金等价物净增加(减少)额         实测 002415 2025H1
现金及现金等价物净增加/(减少)额        实测 000333 2025 各期
现金及现金等价物净(减少)/增加额        实测 000333 2024 年报 ← 括号内词序与括号外相反
```

早期是**逐个追加**（先"增加"，再加"减少"，再加带括号的），每遇到一种新写法就
漏一次。现已改成一个覆盖全族的式子：

```
^现金及现金等价物净\s*(?:增加|减少)(?:\s*/?\s*[(（]\s*(?:增加|减少)\s*[)）])?\s*额\s*$
^现金及现金等价物净\s*[(（]\s*(?:增加|减少)\s*[)）]\s*/?\s*(?:增加|减少)\s*额\s*$
```

**教训适用于本仓其余所有"措辞族"**（现金三项、汇率影响行、期间词列头都已各自
踩过一次）：**按族写一个式子，不要按见到的样本逐个追加**。逐个追加的代价不是
"少匹配一次"，而是每次都要重新发现、重新回归。

## 第 26 轮：修复"行名末字折到下一行行首"

### 真实版式（600276 2026 半年报 p76）

```

权益（或股东权益）合 64,466,430,205.71 61,272,068,641.41

少数股东权益 523,310,211.35 524,754,772.84
```

`_dewrapped` 的"行名在字中间拆开"分支把孤立的 ``计`` 当成下一行的行首，拼出
``计少数股东权益``，而权益行名停在 ``…合``。修法：新增
`_resplit_wrapped_tail()`，只有当"把下一行前 1~2 个汉字接到本行行名末尾"
**恰好等于某个已知术语**时才重切。

### 必须记住的教训：验证谓词不能是前缀式

我第一版用 ``_matches_component_label`` 直接委托 `_field_matches`，而
`parent_equity` 的谓词是 ``^归属于母公司(?:所有者|股东)(?:权益|股东权益)``
**加** ``"合计" in clean``——是"前缀 + 子串"，不是整词。于是
``…（或股东权益）合计`` + ``少`` 也被判成术语，规则**从下一行偷走一个字**：

```
归属于母公司所有者权益（或股东权益）合计少   ← 偷了下一行的"少"
数股东权益                                   ← 自己的首字没了
```

而标准资产负债表恰好就是"完整的归母权益行紧跟少数股东权益行"，因此这条会
命中**常规版式**。子 agent 用一个单元级反例抓到并立刻上报，随后补了两道守卫：

1. `_FIELD_WHOLE_LABEL`：为五个 S2 字段单独做**整词**判定（不改
   `_field_matches`——它的宽松在 `find`/`_recover_wrapped`/单元格抽取里是
   **承重的**，收紧会破坏真实标签）；
2. **行名本身已是完整术语时绝不再接字**。这道守卫是承重的：`_COMPONENT_LABELS`
   里 `attributable_profit` 带 ``.*$``，任何它匹配的行名都已经命中术语，
   守卫先拒绝，否则那会变成第二条偷字路径。

**两条守卫缺一不可**，`tests/unit/test_statement_wrapped_tail.py`（9 例）里
有两个反例分别锁住它们，去掉守卫即失败。

全库实测：**无回归**，600276 由 3/5 变 5/5；`000651 2024-12-31` 在**无守卫**
版本下会丢 `parent_equity`，加守卫后保持通过。

### 本轮修掉的两类换行版式（都是"行名被拆开"）
