# ADR-012：`TextModelProvider` 保留为领域窄接口，agentctl 是它的生产实现之一

**状态：已采纳**
**日期：2026-09-15**
**依据：** ADR-011、Q0 就绪报告 §4.3

## 背景

领域层需要"读一段文本、给一个结构化结论"的能力（证据抽取、摘要）。
可选做法：

1. 领域层直接调用某家模型 SDK；
2. 领域层定义一个窄接口，由外部注入实现。

第 1 种会把"用哪家模型"焊进领域层：换模型要改领域代码，离线测试要联网，
而且模型密钥会渗进量化模块。

## 决策

**`TextModelProvider` 保留为领域侧的窄接口；agentctl 网关是它的
生产实现之一；离线测试替身不变。**

- 领域层只依赖接口，不依赖任何 SDK；
- 生产实现（经 agentctl 网关）在**适配层**，不在领域层；
- 离线测试用确定性替身，因此 `pytest` 不需要模型密钥、不联网。

## 后果

- 领域测试完全离线，符合"无供应商合同、无模型密钥时也能跑确定性测试"
  的交付要求；
- 换模型/换网关只改适配层；
- **代价**：接口必须是"够用的窄"——太窄会逼着适配层做领域判断，
  那等于把领域逻辑挪到适配层。当前接口只做文本进、结构化出，
  语义判断留在领域层。
