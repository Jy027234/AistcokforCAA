# ADR-015：S2 财务数据替代源与小规模 Provider Spike

**状态：已采纳（接入路线）／凭证有效但财务接口无权限**

**日期：2026-09-19**

**决策范围：** S2 的财务输入、替代数据源、PIT/修订处理和试运行降级；不改变 S2 的公式。

## 背景

主规格 §10.4 的 S2 是质量—估值挑战者策略：

```text
quality_rank = mean(rank(F07), rank(F08), rank(F09))
value_rank   = rank(F10)
signal_rank  = 0.5 * quality_rank + 0.5 * value_rank
```

ADR-005 的 T9/T12 证据已经证明，当前 BaoStock 路径没有足够的绝对报表值：

- F07 需要期初、期末归母权益，不能用 `roeAvg` 比率反推；
- F09 需要连续、同口径的营业收入，现有 `MBRevenue` 存在整季缺口；
- F08 即使可以做口径换算，也不能补上 F07 与 F09；
- §10.2 禁止用零填充或静默降低公式要求。

因此“换一个接口”只有在新源同时满足字段、公开时间、修订和行业口径约束时，才可能解除 S2 的关闭状态。本 ADR 记录候选路线，不把文档层字段声明当作真实接入验收。

## 决策

1. **Tushare Pro 作为第一候选的结构化探针源。** 官方接口文档在字段层面覆盖 S2 所需的绝对值和报表元数据，工程接入成本预计低于自行解析全部原始报告。2026-09-19 已用使用者提供的本机 Token 通过 HTTPS 探针确认凭证有效；`income`、`balancesheet`、`cashflow` 三个接口均返回 `40203`（账户无接口权限），所以真实字段、覆盖率、PIT 和修订验收尚不能执行。

   去敏探针结果保存在 `deploy/agentctl-q0/tushare-s2-probe.json`；报告不记录 Token、Token 文件路径、Token 长度或原始响应。可重复探针入口为 `tools/probe_tushare_s2.py`。
2. **巨潮资讯与沪深交易所原始披露作为权威校验和高成本兜底路线。** 这条路线保存 PDF/XML/XBRL 原文并自行规范化，能够保留可追溯的披露证据，但需要承担报告格式、分类标准、修订公告、跨行业科目映射和解析失败处理成本。
3. **AkShare、efinance、easyquotation、adata 不直接解除 S2。** 它们可以作为探针、交叉核对或行情辅助，但必须先通过本 ADR 的字段、PIT、修订、行业和权利闸门；开源库的许可证不自动授予上游数据的存储、模型处理、商用或再分发权。
4. **S2 继续关闭，直到候选源通过全部硬闸门。** 本结论不阻断首期试运行。试运行继续使用已验证的价格基线、快照、研究卡、模拟账本和 F10 当前研究字段；S1 与 S2 的正式对照以及“财务质量改善选股”的结论暂不发布。
5. **任何降低因子数量的实验都必须登记为 `CUSTOM` 新版本。** 例如只用 F10，或使用经独立验证的 F08+F10，均不得沿用 `S2` 名称、版本或验收结论。

代码层同时执行该关闭状态：策略版本接口会以
`SOURCE_PERMISSION_MISSING` 拒绝新建 `family=S2`，实验登记也会重新检查策略
版本，避免升级前遗留的 S2 记录绕过闸门。版本列表通过 `familyGates` 返回机器
可读的关闭原因，供工作台明确显示“未启用”。

## 文档层字段覆盖：Tushare Pro

以下是对官方接口文档的**能力假设**，不是本项目已经取得的实测结果：

| S2 输入 | 官方文档中的候选字段 | 用途 | 尚未证明的事项 |
|---|---|---|---|
| F07 归母净利润 | `income.n_income_attr_p` | 归母净利润 TTM | 每个报告期的覆盖、单位、合并口径和历史修订行为 |
| F07 期初/期末归母权益 | `balancesheet.total_hldr_eqy_exc_min_int` | 平均归母权益 | 是否在目标样本与所有所需期末均有值，以及修订链是否完整 |
| F08 经营现金流 | `cashflow.n_cashflow_act` | 经营活动产生的现金流量净额 | 累计/单季语义、金融业模板和报告类型选择 |
| F08 合并净利润 | `cashflow.net_profit` 或与利润表核对的合并净利润字段 | 现金质量分母 | 与现金流口径是否严格一致，不能凭字段名直接假定 |
| F09 营业收入 | `income.revenue`（必要时与 `total_revenue` 对照） | TTM 与去年同期收入 | 连续季度覆盖、行业口径和累计/单季语义 |
| 报表时点 | `ann_date`、`f_ann_date`、`end_date` | 报告归属期与公开日期 | 日期精度、实际公告时间和历史可查询性 |
| 版本和行业模板 | `report_type`、`comp_type`、`update_flag` | 区分合并/单季/调整前后、公司类型和更新 | 更新标识能否重建历史版本，不能仅凭字段存在下结论 |

官方文档还写明：单只股票历史财报接口需要至少 2000 积分；按季度批量的 VIP 接口需要至少 5000 积分。该权限说明只证明接口的访问门槛，不证明本项目账户拥有权限，也不证明所需历史数据已经可用。

## PIT、修订和行业适用性硬规则

接入任何候选源都必须满足以下规则；仅有当前修订值或只有报告期的接口不能直接进入 S2：

1. **可用时间。** 保存报告期 `period_end`、公告日期、公告时刻（如有）、系统首次捕获时间和来源版本。只有日期没有时刻时，按主规格 §7.3 使用公告日之后第一个交易日盘前作为 `available_at`；不能把报告期末当成可用时间。
2. **PIT 读取。** 决策时点只能读取 `available_at <= cutoff` 的版本。未来公告必须被拒绝；今天重新下载的历史数据不能把 `first_seen_at` 伪造成过去。
3. **修订不可覆盖。** 原始响应或原始报告保留内容哈希；修订、调整前报表和调整后报表以独立版本保存，并用 `supersedes_id` 或等价关系指向被替代版本。`update_flag` 存在不等于修订链已经被验证。
4. **报表口径。** 每个因子必须固定合并/母公司、归母/含少数股东、单季/累计、币种和单位。TTM 不能直接相加四份累计季度值；需要按主规格 §10.1 的衔接公式验证。
5. **行业模板。** 普通工商企业、银行、保险、证券和多元金融不能默认使用同一现金流或收入模板。缺少历史行业分类版本时，只能做当前研究或把对象排除；不得用今天的行业标签回填过去。
6. **权利闸门。** provider 的条款或书面授权必须分别登记 `research_use`、`local_storage`、`model_processing`、`commercial_use` 和 `third_party_redistribution`。任何一项仍为 `UNKNOWN`，不得因“字段可取”而放开相应动作；登记见 `docs/data-rights-register.md`。

## 小规模 Provider Spike

Spike 是一次受限能力验证，不是生产接入，也不应改变当前默认数据源。凭证只通过环境变量或本机安全配置提供，不写入仓库、日志和样本；原始样本只有在权利允许时才入库，否则只保存脱敏映射和哈希。

### 样本与输入

- 建议选择 12 只标的：8 只普通工商企业、2 家银行、1 家保险公司、1 家证券公司；样本同时覆盖不同规模、不同报告披露节奏和至少一个存在历史更正的报告链。若自然样本没有更正，必须把“修订未观测”标为未验收，不能假称通过。
- 每只读取最近 8 个已结束报告期，并补充至少 2 个年度报告期用于 TTM 衔接；保存请求参数、字段列表、响应哈希、空值和失败原因。
- 对每个样本选取可访问的巨潮或交易所原始披露作为抽查基准。抽查数量、容差和单位换算在运行前冻结，不能看完结果后调整。

### 通过条件

以下是本项目建议的 Spike 门槛，属于待执行的工程验收标准，不是已取得的结果：

| 闸门 | 通过条件 | 失败后的处理 |
|---|---|---|
| 字段与覆盖 | 普通工商样本的 F07–F09 所需绝对字段覆盖率建议至少 95%；单条关键值缺失不得填零，直接标记该标的不可入 S2 | 保留失败原因，S2 继续关闭 |
| PIT | 每条财务记录有可复核的公告/实际公告日期；cutoff 早于 `available_at` 时读不到，顺延到保守盘前后可读 | 只能用于当前研究或前向观察 |
| 修订 | 至少一条真实修订链，或明确报告“样本内未观测”，并通过等价合成拒绝用例；原版和修订版均可重放 | 不能声称历史 PIT 已解决 |
| 口径/TTM | 合并口径、单位、累计/单季和归母边界有字段映射；按冻结公式与抽查报告能重算 | 该因子禁用，不用近似值替代 |
| 行业 | 普通工商企业通过统一模板；银行/保险/证券分别标注模板或明确排除 | 仅保留适用行业，不扩大结论 |
| 原文核对 | 抽查报告的关键绝对值、报告期和公告日期在预先冻结容差内一致；差异有解释和留痕 | 进入人工复核或失败 |
| 权利/成本 | 权利登记完成；Token、积分、频率和长期成本可说明；不得把个人/学习许可当作商用授权 | 只允许本地受限探针，禁止生产/外发 |

Spike 的最终产物至少包括：provider 能力卡、字段映射、覆盖与缺失报告、PIT/修订报告、行业适用性表、权利卡和失败原因清单。没有这些产物，即使一次 API 请求返回了数据，也只能标为“计划接入”或“探针运行”，不能标为“测试通过”或“用于正式研究”。

## 试运行降级与 `CUSTOM` 实验

S2 缺失只阻断以下研究结论：S1 与完整质量—估值策略的同池比较，以及质量因子带来增益的因果/收益表述。它不阻断首期价格研究、每日快照、研究卡、事件前向归档、有限模拟器、组合账本和工作台试运行。

在候选源尚未通过 Spike 前：

- 保持 `S2` 和依赖 F07/F08/F09 的正式回测关闭；
- 继续显示 F10 时标注其来源、覆盖率和缺失原因，不把 F10 单独称作 S2；
- 不用零、当前修订值或跨源静默拼接补齐质量排名；
- 如确有实验需要，新增例如 `CUSTOM-S2-LITE-v1` 的独立登记，明确因子集合、证券池、行业排除、版本日期和证据来源。该实验必须拥有自己的结果、快照和验收，不能写入 S2 的历史结论。

只有在 Spike 全部硬闸门通过、适配器和 PIT 黄金用例完成、权利状态允许相应使用后，才可新建 S2 的可运行版本；新版本仍需与 S1 同池报告覆盖率、行业过滤和未入选原因。

## 当前状态

截至 2026-09-19：

- 使用者提供的本机 Token 文件已用于一次去敏 HTTPS 探针；Token 没有写入命令参数、报告或仓库；
- 凭证本身有效，但 `income`、`balancesheet`、`cashflow` 均返回 `40203` 无访问权限。因此当前账户无法开始字段和覆盖率 Spike；这不是网络失败，也不是 Token 无效；
- 已核对官方文档层能力和仓库已有 BaoStock 实测；真实财务行尚未取得，覆盖率、口径、PIT 和修订链均保持“未验收”；
- CNINFO/交易所路线被记录为权威、高成本备选，不宣称已经完成财报解析；
- 因此 S2 状态仍是“缺必需输入，继续关闭”，而不是“已接入但未展示”。
