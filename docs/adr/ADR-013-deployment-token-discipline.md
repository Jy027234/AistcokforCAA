# ADR-013：静态 master 令牌不下发到产品，部署一律用 `--token-env`

**状态：已采纳**
**日期：2026-09-15**
**依据：** Q0 就绪报告 §4.4

## 背景

Q0 实测中发现一个**测试接线错误**，值得单独记为纪律：

我曾把产品令牌当作服务端静态 `--token` 启动 agentctl，于是租户校验被
短路成 master，测试里"伪造租户被接受"。那不是 agentctl 的漏洞，而是
**我的接线把闸门绕过了**。用独立 master 令牌后所有边界都正常拒绝。

这条教训的普适形式是：**测试接线本身是安全前提，必须断言而不是假定。**

## 决策

| 项 | 决定 |
|---|---|
| 服务端启动 | 一律 `--token-env`，从环境变量读 master 令牌 |
| 静态 `--token` | **不用于任何部署**；仅限本地一次性排查 |
| 产品令牌 | 独立签发、限制到具体能力（如 `frontdesk.message`） |
| master 令牌持有者 | 由部署方掌握，不下发到产品配置、不进代码库 |
| 凭据存储 | 环境变量或密管服务；`.gitignore` 覆盖 `.env` / `*.key` / `.secrets/` |

## 后果

- 伪造租户、越权能力、跨租户访问在**生产接线**下会被拒绝；
- 反向要求：任何验收若涉及身份边界，必须先声明用的是哪种令牌。
  否则"通过"可能是因为闸门被短路，而不是因为闸门有效；
- Q0 报告 O7（生产部署的令牌方式与持有者）仍需部署方确认，
  但**默认姿态已定为最保守的那种**。
