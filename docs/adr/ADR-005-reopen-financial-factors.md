# ADR-005：重开 F07–F10（财务因子）的 PIT 可行性

**状态：已采纳（方向）／实现待验收**
**日期：2026-09-14**
**修订：** ADR-003 中"F07–F10 默认关闭"的理由

## 背景

ADR-003 关闭 F07–F10 的理由是：**免费源不提供 PIT 财务数据**，
只返回当前修订版，无法取得"某次修订当时可见的值"。

T7/T8 实测发现这个理由**现在站不住**：BaoStock 的季频财务数据带
`pubDate`（公布日）：

```
茅台 2026Q2：pubDate=2026-08-15  statDate=2026-06-30
roeAvg / npMargin / gpMargin / netProfit ...
```

有了公布日，"这条财务数据在某个决策时点是否已经可知"就**可以证明**，
不必再把历史时点伪造成过去。

## 决策

重开 F07–F10 的可行性评估，但**不直接解除 ADR-003 的全部限制**：

| 项 | 决定 |
|---|---|
| F07–F10 的计算与展示 | ✅ 允许，标注为 `RECONSTRUCTED` PIT |
| 历史财务回测 | 🟡 需先实现并验收下述可用性规则 |
| "历史因果验证"类结论 | ❌ 仍不得声称（ADR-003 未变） |
| 前向观察 | ✅ 仍是首选（ADR-003 未变） |

## 必须实现的可用性规则

`pubDate` 精确到**日**，不提供时刻。因此当日盘中是否已知无法证明。
按 D04 已确立的保守规则处理：

> 只有日期没有时刻时，可得时点**不得早于次一交易日盘前**。

即：某条财报在 `pubDate` 之后的下一个交易日的盘前才视为可用。
这与公告的处理一致，且两个方向都不会误判为"提前知道"。

## 后果

- 需要新增财务数据的入库路径（`corporate`/`financials` 数据集），
  以及 `feature_value` 的 PIT 读取；
- 需要为每个财务因子记录 `available_at`（由 `pubDate` + 保守规则推出）
  与 `available_basis=RECONSTRUCTED`；
- 需要新增验收用例：**用未来才公布的财报去回答过去的决策，必须被拒绝**；
- README 与研究结论的表述需同步：F07–F10 可用于当前研究，
  但"某条财务数据在历史上某时点已可见"这句话需要附上推导依据。

## 实测修订（2026-09-14，T9 能力审计之后）

T9（`tests/integration/t9_financial_capability.py`，7/7）逐字段核对了
数据源与规范 §10.1 的公式，结论**收窄了本 ADR 的适用范围**。

### 三项实测事实

| 事实 | 证据 |
|---|---|
| `pubDate` 齐全，`statDate < pubDate` | 6/6 季度有值，跨度 2025-04-30 ~ 2026-08-15 |
| **同一数据源内口径不一致** | `profit.netProfit`/`roeAvg` 为**年内累计**（同年逐季不减）；`cash_flow.CFOToNP`/`CFOToOR` 为**单季** |
| **只有比率，没有绝对报表值** | 全量字段里没有归母权益、经营现金流净额、营业收入的绝对值 |

口径判据用**同一自然年内单调不减**这一结构性性质，不用比值阈值的启发式。
我第一版用"Q2/Q1 > 1.5 即累计"，把 `netProfit` 误判成累计——茅台
46.99/27.77 = 1.69 只是季节性陡增。改用结构判据后与公开事实核对：
茅台 2025 年 Q4 = 853.1 亿（若为单季则四季累加 2269.7 亿，不可能），
故 Q4 即全年，确为年内累计。

### 四个因子的可行性

| 因子 | 可行性 | 原因 |
|---|---|---|
| F07 ROE_TTM | ❌ **不可计算** | 公式要**绝对归母权益**（期初期末平均）；数据源只给 `roeAvg` 累计比率，无法还原绝对权益 |
| F08 现金质量 | 🟡 需口径换算 | `CFOToNP` 与 `netProfit` 同口径（累计），相乘得累计经营现金流再滚动 |
| F09 营收TTM同比 | ❌ **不可计算** | `MBRevenue` 存在**整季空值**（实测 2025Q1、2026Q1 皆空），TTM 会因缺项算错 |
| F10 盈利收益率 | ✅ 可计算 | TTM 净利润 = 当期累计 + 上年全年 − 上年同期累计；市值 = `totalShare` × 收盘价 |

### 对 S2 的影响（重要）

规范 §10.3 的 S2「质量-估值挑战者」公式是：

```
quality_rank = mean(rank(F07), rank(F08), rank(F09))
value_rank   = rank(F10)
```

**F07 与 F09 在 BaoStock 上无法计算**，因此：

> **S2 在当前免费数据源下做不成。** 不是"暂未实现"，而是缺必需输入。
> 即使实现了 F08 与 F10，`quality_rank` 也缺两个分量，
> 按 §10.2「缺失值不得用 0 填充」不得补齐——补齐出来的 S2 是另一个策略。

要做 S2，需要**提供绝对报表值**的财务数据源（付费供应商或交易所原始报表）。

### 因此本 ADR 的实现范围

- ✅ 实现 F10，带 `pubDate` 保守规则与 PIT 拒绝用例；
- 🟡 评估 F08 的口径换算，但**不**宣称 S2 可用；
- ❌ F07 / F09 保持关闭，并在能力卡与 README 中注明原因。

## 实现结果（2026-09-15）

F10 已实现并在真实全市场上验收（`tests/integration/t12_f10_real.py`，7/7）。

### 可用性规则已实现并有拒绝用例

可得时点 = **公布日之后第一个交易日的盘前**（09:00 CST）。取"严格之后"
而不是"当日"：pubDate 不提供时刻，公告可能盘中或盘后发布，当日已知
无法证明。宁可晚一天，不可早一天。

`tests/golden/test_financials_pit.py` 用 15 条用例覆盖拒绝路径，
包括：公布当日盘中与盘前都看不到该财报；周末公布顺延到周一；
五一长假（4-30 公布）顺延到 5-06（用工作日近似会提前 5 天）；
日历覆盖不到时抛错而不是猜。

### TTM 公式（修正过一次）

正确写法是**滚动 12 个月**：

    当期累计 − 上年同期累计

我最初写成"当期累计 + 上年年报 − 上年同期累计"，对 2026Q2 会多出
一整年利润（4.4 vs 0.4，单位亿），F10 因此被系统性低估约 10 倍。
这种错误不会报错，只会让"盈利收益率"看起来异常低——而低收益率看起来
像"估值高"，是一个完全说得通的结论，肉眼查不出来。

Q4 是完整 12 个月，直接取全年值；年报经审计且可能重述，比用三季报推导
更权威，且不要求有上年数据。

### 真实覆盖率与已知缺口

全市场 900 只研究池（BaoStock 采集，0 失败）：

| 结果 | 只数 | 占比 |
|---|---|---|
| **算出 F10** | **832** | **92.4%** |
| 被数据质量闸门拒绝 | 66 | 7.3% |
| 净利润字段为空 | 2 | 0.2% |

值域 [-0.0822, 0.1178]，中位 0.0024，**28.1% 为负**（亏损未被截断为 0）。

**已知缺口**：7.3% 的标的在同一自然年的**中期**序列上出现累计值下降，
可能是年报重述或供应商口径不一致。原因不明时**不算**，而不是算一个
错的出来——TTM 公式依赖"年内累计"这一口径，口径不成立时结果无意义。
这 66 只在研究结论中必须显式排除，不得静默当作缺失。

### 仍然关闭的

- **F07**：需要绝对归母权益，数据源只给 `roeAvg` 累计比率。
- **F08**：`CFOToNP` 与净利润同口径（年内累计），可推导；
  尚未实现，也不影响 F10。
- **F09**：`MBRevenue` 有整季空值。
- **S2**：`quality_rank` 需要 F07、F08、F09 三者，两个不可得且 §10.2
  禁止用 0 补齐，因此 S2 在当前数据源下做不成。

## 替代源进展（2026-09-19）

ADR-015 已把 Tushare Pro、巨潮/交易所原始披露及其他免费封装源纳入独立
能力路线。Tushare 官方文档提供 F07--F09 所需的绝对报表字段，但本机真实
HTTPS 探针得到的结论是：使用者提供的 Token **有效**，`income`、
`balancesheet`、`cashflow` 三项接口均返回 `40203`（账户无访问权限）。

因此本 ADR 的因子结论暂不改变：F10 继续可用，F07/F09 与 S2 继续关闭。
这次结果只证明阻断点已经从“是否有候选字段”收窄为“当前账户没有三项财报
接口权限”；尚未取得真实报表行，不能推断覆盖率、单位、PIT 或修订链通过。
完整接入条件与降级方案见 `ADR-015-s2-alternative-data-provider.md`。
