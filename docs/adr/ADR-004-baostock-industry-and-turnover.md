# ADR-004：行业分类与成交额采用 BaoStock 作主来源

**状态：已采纳**
**日期：2026-09-14**
**依据：** `tests/integration/t7_baostock_industry.py`（13/13）、
`t7_universe.py`（7/7）、`t8_baostock_provider.py`（20/20）、
`docs/data-capability-baostock.md`

## 背景

两处数据缺口在真实数据验收中被暴露：

1. **行业分类没有权威来源。** 研究池 24 只的行业是我在配置文件里手工声明的
   粗分类（`SW_BANK`、`SW_MEDICAL`…）。问题有两层：
   - 只覆盖这 24 只，**扩池即失效**；
   - 实测与权威分类有两处实质不符——迈瑞医疗（300760）属
     `C35 专用设备制造业`而非医药；爱尔眼科（300015）是 `Q84 卫生`。
     手工声明把它们写成同一行业，会让"同行业可比"的横截面排名与
     行业上限的约束对象都算错。

2. **成交额缺失。** §11.2 的流动性下限按成交额（`liquidity_min_avg_amount_cents`），
   而腾讯日线只有成交量、没有成交额。此前该参数默认 `None`（不筛），
   因为给一个默认阈值会让所有标的被排除，而用"价格×成交量"估算是拿一个
   未观测的数字做准入判断。

T7 实测确认 BaoStock 两项都能补齐，且与腾讯源交叉一致（收盘价逐分相同）。

## 决策

| 数据域 | 主来源 | 备用/校验 | 说明 |
|---|---|---|---|
| 日行情（OHLCV） | **BaoStock** | 腾讯仅作交叉校验 | 两者实测逐分一致；换主来源是为了让成交额与价格同源，避免同一行数据来自两个口径 |
| 成交额 `amount` | **BaoStock** | 无 | 免费源中唯一提供成交额且单位明确的 |
| 换手率 `turn` | **BaoStock** | 无 | 顺带获得，暂未使用 |
| 行业分类 | **BaoStock 证监会分类** | 无 | 口径登记为 `CSRC-2012`，写入 `classification_version` |
| 公告与公司行为 | 巨潮（不变） | 上交所/深交所 | 本次不动 |

按 §280「同一字段设定主来源，备用来源不能在主来源失败时悄悄混入」：
腾讯降级为**交叉校验**，不再作为行情主来源；两者不一致时应当报错，
而不是取其一继续。

## 已知限制（必须随结论一起引用）

**行业分类不能用于历史时点查询。** `updateDate` 在全量 5553 条里只有一个
取值，说明它是"本次快照日期"而非"分类变更日期"。因此：

> 行业分类与行情同属 `RECONSTRUCTED` 口径——可用于**当前**研究，
> **不能**回答"某个历史时点它属于哪个行业"。D05 那类"历史分类不被当前
> 列表替换"的判定仍需另找来源。

T7 把这条写成了断言：将来 BaoStock 提供变更史时，断言会失败并提醒升级。

## 后果

- 研究池行业改为证监会口径，原手工值保留在
  `declared_industry_*_legacy` 字段便于回溯；
- `fetch_guard` 的域名白名单**管不到 BaoStock**（它走裸 socket
  `www.baostock.com:10030`）。T8 为此实现了等价的留证：内容寻址落盘 +
  sha256 收据，与 HTTP 源共享同一套收据语义；
- 批量查询慢（全量 25~90 秒，服务端限速），必须缓存；
- 许可证是 **BSD（代码）**，不等于数据许可。BaoStock 上游是交易所披露
  数据，与抓取消费级网站性质不同，但按 §17.2 权利仍需显式确认，
  在此之前**不得进入模型外发链路**。
