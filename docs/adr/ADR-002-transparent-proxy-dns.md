# ADR-002：抓取环境的穿透式代理与 DNS 防护降级

**状态：已采纳（需用户确认是否为本机预期配置）**
**日期：2026-09-13**

## 背景

T4.3 排查发现本机 DNS 由代理接管，所有域名解析到伪 IP 网段：

| 域名 | 解析结果 |
|---|---|
| push2.eastmoney.com | 198.18.0.225 |
| github.com | 198.18.0.85 |
| pypi.org | 198.18.0.77 |

旁证：存在名为 `Meta`、下一跳 `198.18.0.2` 的网络接口；DNS 服务器 `fdfe:dcba:9876::2`；
`198.18.0.0/15` 属 RFC 2544 基准测试保留段。这是代理/VPN 的 fake-IP 实现，
不是攻击，也不是本机缺陷。

## 问题

主文档 §17.3 要求抓取器"阻止访问内网、云元数据地址"。我们的守卫通过
"解析主机名再检查 IP" 实现，但在此环境下该检查会拒绝**一切**出站请求。

## 决策

新增 `FetchPolicy.trusted_proxy_networks`：

- **默认空集**：不信任任何代理网段，行为与之前一致（严格）。
- 运维方需**显式声明**（环境变量 `AQUANT_TRUSTED_PROXY_NETWORKS`）才放行。
- 放行后仍强制：主机名白名单、协议、端口、体积上限、逐跳重定向复校。
- **云元数据地址（169.254.169.254 等）即使声明了代理网段也仍被拒绝**，有测试保证。

## 后果

- ⚠️ **这是真实的防护降级**：声明代理后，DNS→IP 检查不再能证明连接的真实目的地，
  因为连接终止在本地代理。剩余防护为"仅主机名白名单"级别。
  已在模块文档与测试中明示，不以"检查通过"掩盖。
- 若本机代理配置发生变化（例如关闭代理直连），未声明的伪 IP 会被正常拒绝，
  这是预期行为而非故障。

## 待用户确认（不阻塞开发）

- 该代理是本机预期配置吗？若否，应关闭代理或改用直连出口。
- 若代理会长期存在，建议在部署文档中固定该环境变量，避免每个环境重复排查。
