# 个人研究与模拟流程优化

用户于 2026-10-13 确认以个人投资研究与模拟为主，授权依照前端评估制定目标并持续优化。本批以既有产品能力和主规格 §5、§11.3 为基线。

## 目标与范围

日常闭环：今日变化 → 股票研究与比较 → 检查模拟资格、形成方案 → 人工确认或明确维持不动 → 回看原判断与模拟结果。

本批集中交付：

1. 四个主要入口：今日、研究、模拟组合、复盘；数据诊断和运行设置进入次级入口，旧深链继续有效。
2. 首页与草稿区分未计算、待处理、等待行情、待确认、已冻结、已执行；未计算不能显示规则全部通过或无需调整。
3. 研究选择带证券和研究版本进入模拟资格核验；版本不一致、不在模拟范围或资格未通过时，说明原因，不自动替换来源。
4. 研究中的模拟操作迁入模拟组合，保留各路径的输入边界；默认呈现日期和下一步，快照 ID、哈希及诊断按需展开。
5. 明确记录维持当前组合的决定及理由；使用服务端已有 NO_CHANGE 接口，绑定页面所见快照，不产生订单或改写账本。
6. 复盘首先呈现个人原判断与保存方案；工程回放、对照及实验登记进入次级区域。没有可靠绑定时不猜测将成交或收益归给某次判断。

## 验收标准

- 从研究进入模拟后保留证券选择，经当前同版本资格校验才可加入草稿；导航回返可以继续研究筛选/比较及未提交方案。
- 未预览、无规则结果、不可模拟和读取错误均如实表达；业务金额继续来自声明的服务端或显式演示数据。
- 预览、确认、冻结和模拟执行各阶段有清楚状态；等待执行日行情属于正常过程，不能伪造成交或成功。
- 维持不动可保存理由及原快照并在复盘读取；未保存不显示成功，重复点击由提交状态拦截。
- 原有研究公式、证据、规则选择、实验和账本能力仍有可达入口；时点、资格、人工确认与原记录不可变边界保留。
- TypeScript、前端构建、相关组件行为检查及界面契约检查通过；相关决策/模拟 API 测试通过。
