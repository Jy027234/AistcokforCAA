# 数据权利登记表

**性质：** 本表是**声明**，不是法律意见。
**日期：** 2026-09-15 · **依据：** §17.2（未知默认不开放）、§826
**代码：** `src/aquant/domain/data/rights.py`、`src/aquant/domain/ai/egress.py`
**强制：** `tests/security/test_model_egress_gate.py`

---

## 一、六个字段各管什么

| 字段 | 管的事 | 风险层级 |
|---|---|---|
| `research_use` | 能不能拿它做研究 | 低 |
| `local_storage` | 能不能存进本地库（含归档原文） | 低 |
| `excerpt_display` | 能不能把原文片段展示给使用者 | 中 |
| `commercial_use` | 能不能用于商用 | 高 |
| `third_party_redistribution` | 能不能再分发出去 | 高 |
| **`model_processing`** | **能不能送进模型上下文** | **最高** |

**为什么把 `model_processing` 单独隔离**：把抓来的数据发给模型厂商，
在法律上是**对外披露**，与其他五项不是一个量级；而且它是唯一
"一旦做了就无法收回"的一项——数据已经在第三方手里了。

### 2026-09-15：使用者授权（两轮）

**第一轮**：使用者在了解"消费级网站最需要本人核对条款"之后，确认放行。
**第二轮**：使用者进一步明确"片段展示也放开，允许送进模型"。

登记表据此记为两类，**不可混同**：

| 来源组 | basis | 含义 |
|---|---|---|
| 消费级网站 | `USER_AUTHORIZED` | 使用者就该项**直接表态** |
| 公开披露源 | `PUBLIC_DISCLOSURE`，备注"模型外发依据为推论" | 使用者**未直接表态**，是我方按其意图推论 |

**为什么要分两类**：推论可能是错的，而"谁说的"决定了复核时该问谁。
若把推论记成使用者的直接授权，复核时会去问一个从未做过该确认的人。

#### 必须写明：`model_processing` 无法收回

它是六项里唯一"一旦执行就无法收回"的一项——数据已经离开本机、
进入第三方。使用者是在被告知这一点之后授权的，因此登记表记录该授权。

**但依据类型不是 `TERMS_REVIEWED`**：来源条款本身**没有**经过法律审阅。
当前状态是"使用者在知晓风险后授权使用"，而不是"条款允许"。
这两件事的差别在出问题时才显现，因此必须现在写清。

#### 未随授权放开的两项

`third_party_redistribution`（再分发）与 `commercial_use`（商用）**保持关闭**：
交易所对行情数据另有商业授权安排，原始信息公开不等于可以转售。
这与"发送给模型做处理"是不同性质的行为——前者是**再发布**，后者是**处理**。

例外：`synthetic-fixture` 是本资料包自带的合成数据，是我们自己的，
其书面许可覆盖全部六项。

### 判定理由

1. **公开披露信息源**（BaoStock、巨潮、交易所官网）
   数据本身是**法定公开披露**的内容。研究使用、本地保存、片段展示的空间
   明显更大。模型外发按上文的**推论**记入。
   但**再分发与商用不放开**：交易所对行情数据另有商业授权安排。

2. **消费级行情网站**（腾讯、新浪、东财）
   这些是**企业服务条款**约束其接口，而不是公开披露制度。
   使用者已明确授权四项，登记表据此记录，但依据类型是 `USER_AUTHORIZED`
   而非 `TERMS_REVIEWED`——**这一组最需要使用者本人持续核对条款**。

3. **范围由守卫固定**
   可外发来源清单写在 `tests/security/test_rights_registry_guard.py` 里。
   任何改动都必须同时改那份清单与本文档，否则测试会失败——
   这是为了让安全边界的变动出现在 code review 与 git diff 里，
   而不是悄悄生效。

### ❌ 不等于 "PROHIBITED"

当前值全部是 `UNKNOWN`（代码中），表中的 ❌ 表示**不开放**。
程序中 `UNKNOWN` 与 `PROHIBITED` 都返回 False，但含义不同：

* `PROHIBITED` = 已确认不允许，不应再尝试；
* `UNKNOWN` = 未确认，**可以**通过补充依据改为允许。

区分它们是必要的：否则"没查过"和"查过说不行"会混成一件事，
将来谁也不知道哪些还能争取。

## 三·补：费率参数的来源（不属于「数据权利」，但同样需要出处）

**为什么记在这里：** 费率不是数据源，但它和「某个数字从哪来」是同一类问题。
费率表曾经整张都是合成测试费率，而真实快照上的成交与盈亏一直用它计算——
**数字算得出来，只是没有依据**。修复之后，每一项费率都必须能回答出处。

| 费率项 | 取值 | 性质 | 出处 | 可否复核 |
|---|---|---|---|---|
| 印花税（卖出方） | 0.0005 | 法定 | 财政部、税务总局公告 2023 年第 39 号，2023-08-28 起减半 | 文号可查；留证见下 |
| 过户费（双向） | 0.00001 | 行业标准 | 中国结算：关于降低股票交易过户费收费标准的通知，2022-04-29 起 | 原文可查；留证见下 |
| **券商佣金** | **无权威值** | **合同约定** | （无）—— 必须由使用者按自己的费率提供 | 不适用 |

**留证：** `tools/fetch_fee_sources.py` 把前两项的页面抓下来存档，
档案在 `deploy/agentctl-q0/fee-sources.json`，原文在
`deploy/agentctl-q0/fee-sources/`（文件名即内容哈希）。
`tests/security/test_verified_fees.py` 会核对**留证字节的哈希**——
那两份文件靠字节说话，因此 `.gitattributes` 里标了 `-text`（不做行尾转换）。
这一点是被可复现闸门抓出来的：`git archive` 导出时 CRLF 被归一化成 LF，
哈希当场对不上。

**已知限制（如实记录）：** 两条留证链接都是**转载页**，不是发布机关原件——
发布机关站点在本机（穿透式代理）下或证书不匹配、或禁用了
legacy renegotiation。转载页保留了文号、发布部门、发布日期与实施日期，
足以核对费率；但它不是原件，这一点记在档案的 note 里，不假装是原件。

**佣金为什么不做默认值：** 替使用者填一个数字，等于又制造一处
「看起来有依据的事实」。因此它是显式参数（`AQUANT_COMMISSION_RATE`），
不给就不许在真实数据上跑；用示例值时必须标
`commission_source=UNCONFIGURED_DEFAULT`，让「这是个假设」可见。

## 四、如何放开某一项

放开 `model_processing` 需要：

1. 在该来源的条款或书面授权里找到允许"发送至第三方处理"的依据；
2. 在 `src/aquant/domain/data/rights.py` 里把对应来源的
   `model_processing` 改为 `ALLOWED`，并在本表登记依据与日期；
3. 跑 `tests/security/test_model_egress_gate.py` 确认闸门行为随之改变
   （该测试会断言"未授权来源仍被拒绝"，因此改错会失败）。

代码里 `ALLOWED` 是**唯一**能让 `can_enter_model_context()` 返回真的值。
