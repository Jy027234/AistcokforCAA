# S2 数据采集与可用性实施方案

编制日期：2026-09-28，北京时间。代码核对基线：`1a02623bb760fc47370522f07ff53d0cfe24c03d`。

**文档性质：交给其他 AI 的实施方案；本文没有宣称下述新增能力已经实现。** 实施方先核对当前 HEAD 和工作区，保留其他进程及开发者的未提交产物。本文的来源结论是既有采集记录，不是对未来接口稳定性或全市场覆盖的保证。

## 1. 交付目标和实施边界

目标是让产品在明确的证券范围和决策时点上，使用可追溯的财报事实与同日市值，计算完整 S2，并能持续更新。S2 是现有“质量—估值挑战者”策略，其 F07—F10 公式和行业适用规则保持主规格含义。

采用以下路线：**巨潮官方披露作为已经接通的主路径，深交所作为已验证样本的深市备源；确定性程序批量采集，模型处理困难版式，机器校验正常样本，人工仅处理无法消除的歧义；先实现前向可用，再扩展覆盖和可证明的历史重建。**

实施方应交付三项可见结果，依次验收，不把全部历史完善作为前向使用的前置条件：

1. 固定样本范围完成正式事实入库、匹配快照的 F07—F10、S2 排名及逐证券排除原因。
2. 对配置研究池建立可恢复的批量初始化和公告增量更新，每只证券有明确状态；合格范围可持续使用。
3. 在原始发布档案、版本链和历史市值均可证明的范围内，提供独立的历史重建路径。无法证明的期间明确不可回测。

本次不扩展金融业专用因子、新闻情绪、付费数据源、真实交易或新产品界面。已有 S1 的可用性不因 S2 个别缺口而关闭。AI 研究可以复用已采集的原文和引用，但不能把模型解释写回财务事实。

主规格依据：仓库根目录 `A-Quant-Lab_开发文档_v0.2.md` §7.2—7.3、§10.1—10.4；现有数据边界见 `docs/data-requirement-matrix.md`。本文提出的机器验证协议、通用来源适配、分范围准入和历史读取修正，均属于**待实施**内容。

## 2. 已经取得的证据，以及还缺什么

| 项目 | 已取得的证据 | 不能据此宣称的能力 |
| --- | --- | --- |
| 官方 PDF 能否提供数值 | 原有 8 只、5 个报告期试点覆盖 128/128 个必需指标—期间候选值 | 不等于 128 条正式 PIT 事实；现有试点正式事实为 0 |
| 公式是否可算 | 7/8 只的 F07—F09 候选诊断可算；601012 因合并净利润 TTM 非正被规则排除 | 不等于完整 F10、同池排名或历史回测；非正分母不是采集失败 |

| 新版式样本 | 300502 的 2026H1 已提取五项绝对值 | 当时实跑复用了先前归档索引后继续下载，不能冒称一次 CLI 全链路成功；也未补全该股五期 |
| 深交所 | 300502 2026H1、000651 2025FY 的官方检索与 PDF 下载成功，PDF 与巨潮对应文件字节一致 | 尚未证明全市场、长历史、多页真实检索和完整更正链 |
| 上交所 | 官网页面与脚本可达 | 猜测参数的 API 返回空，不代表该报告不存在；尚未接通可靠的同报告检索—下载路径 |
| 总市值 | 2026-09-22 腾讯路径曾覆盖 900/900；F10 诊断有值 898/900，另 2 只财务期间不足 | 不代表今天市值已就绪，更不能用当日市值代替历史市值 |

**当前主要阻碍已经从“官方原文有没有这些数”转为“能否批量发现、准确提取、处理修订并进入正式读取链”。** 继续重复查询缺字段的接口，或只增加候选 JSON，不能独立完成这个目标。

既有证据入口：`docs/s2-cninfo-batch-candidates.md`、`docs/s2-exchange-disclosure-probe-20260928.md`、`docs/adr/ADR-015-s2-alternative-data-provider.md`。

## 3. 每只股票到底采什么

### 3.1 最小业务字段

| 规范字段 | 必须取的口径 | 用途 |
| --- | --- | --- |
| `net_profit_attributable` | 合并利润表归属于母公司股东的净利润，年内累计 | F07 分子、F10 分子 |
| `net_profit_consolidated` | 合并利润表净利润，含少数股东损益，年内累计 | F08 分母，不能换成归母净利润 |
| `operating_cashflow` | 合并现金流量表经营活动产生的现金流量净额，年内累计 | F08 分子 |
| `revenue` | 合并利润表“营业收入”，年内累计 | F09；不能无条件映射“营业总收入” |
| `parent_equity` | 合并资产负债表归属于母公司所有者权益，期末余额 | F07 的 TTM 起止端点平均权益 |
| 决策日总市值 | 与目标已发布快照的行情日一致的总市值 | F10 分母，按交易日采集 |

还必须保存公司与证券身份、报告期、合并/母公司口径、累计/单季性质、币种单位、原始公告、发布时间精度、修订关系、归档收据、首次捕获时间和可用时间。只保存五个金额不构成合格 S2 数据。

流量 TTM 使用“上一完整年度 + 当年累计 − 上年同期累计”；年末直接使用全年数。金额采用十进制定点计算，统一人民币元，同时保留原表的元/千元/万元及换算依据。缺失保持缺失，负数保持符号；括号、破折号、空格须按表格语义区分，不能统一转零。

公式：F07 = 归母净利润 TTM / 平均归母权益；F08 = 经营现金流 TTM / 合并净利润 TTM；F09 = 本期收入 TTM / 上年同期收入 TTM − 1；F10 = 归母净利润 TTM / 决策日总市值。分母与行业规则复用现有引擎，不能为提高覆盖率减少因子。

### 3.2 期间由程序生成，不能长期写死“五份财报”

调用 `src/aquant/domain/research/s2.py::required_s2_periods(latest_period_end)` 生成字段—期间清单。最新期间来自该证券在目标时点可用的已披露报告，不能只按系统日期推断。新报告已公开但解析失败时应显示更新待处理，不能静默把旧报告标成最新。

以 2026H1 为例，**现有计算器真实依赖 16 个指标—期间值**：

| 报告期 | 必需字段 | 数量 |
| --- | --- | ---: |
| 2024-06-30 | 营业收入 | 1 |
| 2024-12-31 | 营业收入 | 1 |
| 2025-06-30 | 归母净利润、合并净利润、经营现金流、营业收入、归母权益 | 5 |
| 2025-12-31 | 归母净利润、合并净利润、经营现金流、营业收入 | 4 |
| 2026-06-30 | 归母净利润、合并净利润、经营现金流、营业收入、归母权益 | 5 |

这个清单包含现有计算器的同公告核验依赖，不应凭公式印象删去某一项。Q1、Q3、年末所需期间不同，由同一个函数生成。为后续增量复用，可在已下载报告中顺带提取五项；验收分母仍按实际必需清单计数。

### 3.3 证券范围

实施开始重新读取 `configs/real-pool-csrc.yaml`。本次核对为 900 只，其中制造业 C 类 664 只、金融 J 类 28 只、其他非金融 208 只。

- 先用原有 8 只闭环，并用 300502 检验非固定版式。原有名单为 `000333、600519、601012、000651、600276、002415、300750、688981`；与现有试点和证据清单核对后固化到运行 manifest，不重新随意挑选成功样本。
- 普通工商 S2 并不天然限于制造业。随后将候选范围扩展至 872 只非金融证券；每类版式与口径须通过验证，不能仅凭“非金融”自动判定模板适用。
- 28 只金融证券明确记为模板不支持，不计为接口抓取失败。科创板、创业板的研究资格与当前模拟交易板块限制分别处理。
- 每轮固化目标名单、行业版本、期间清单、快照及 cutoff。发现失败后不能缩小分母，转而报告“100% 成功”。

## 4. 来源路由：复用成功路径，限制无效探索

| 数据任务 | 首选和备选 | 使用边界 |
| --- | --- | --- |
| 沪深财报发现、全文、原始公告 | 现有巨潮 `CninfoClient` | 已有主要组件；组织 ID 通过官网搜索获取，不能从股票代码拼造 |
| 深市公告备源 | 深交所 `POST /api/search/content` 与官方 PDF | 先把成功探针工程化；通过身份、分页、归档验收后可配置为深市优先源 |
| 沪市官方备源 | 上交所官网实际使用的查询协议 | 单独限定一次调查预算，例如半个工作日；须从官网脚本/官方请求证据确定协议，无结果就回退巨潮，不阻塞主线 |
| 决策日市值 | 已有腾讯收盘快照；东方财富显式分页备源 | 保留行情日、原始响应及批次收据；东方财富不使用超大单页假装全量 |
| 数值辅助核对 | 已验证的交易所概览、BaoStock、mootdx 等 | 仅核对语义相同部分；不把比率反推金额，不把当前覆盖当历史版本证据 |

Tushare 付费路径不进入本方案。Sina 财务沿用现有受限使用边界。AkShare、efinance 等包装库可以降低调用成本，但不能自动补出上游没有的字段、公开时点或修订链，不为每个包装库建立一套平行流程。不依赖用户逐股票操作 Kimi/iFinD。

来源用途沿用 `docs/data-rights-register.md` 及现有守卫：本方案针对已经登记的个人研究、本地存储和允许的模型处理；登记依据与来源 ID 如实保留，不顺带扩大商业使用或原始数据再分发范围，也不对已授权用途反复请求确认。

**来源切换按一份报告或经过验证的报告版本包进行，不逐字段静默拼源。** 两站 PDF 哈希相同证明原文字节一致和来源可互证，不等于两份独立会计证据。保留两站各自文档 ID、URL、收据及首次观察时间，选定一个规范报告身份供计算器使用。不同文件哈希先判定是否修订/摘要/不同期间，不能仅按“时间更晚”覆盖。

### 4.1 深交所可复用的实测请求

下面是 **2026-09-28 已验证样本的网页请求形式，不是交易所承诺稳定的开放 API**：

```text
POST https://www.szse.cn/api/search/content
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Accept: application/json
X-Requested-With: XMLHttpRequest
Referer: https://www.szse.cn/disclosure/listed/fixed/index.html?stock=300502

keyword=300502
range=title
channelCode[]=fixed_disc
time=1787587200000
endTime=1787673600000
currentPage=1
pageSize=20
```

日期窗口为北京时间 2026-08-25 00:00 至 2026-08-26 00:00。边界包含关系尚未验证，接入时用边界样本确认，并通过重叠窗口和 ID 去重防漏。全类别检索使用 `channelCode[]=listedNotice_disc`，对应页面为 `/disclosure/listed/notice/index.html?stock=300502`。

响应关键信息为 `currentPage`、`pageSize`、`totalSize` 与记录中的 `id`、`doctitle`、`docpubtime`、`docpuburl`、`doctype`。标题可能带 HTML 标签；样本没有独立证券代码字段，必须核对原文公司身份，不能将关键字命中视为身份校验通过。`docpubtime` 样本只有日期级含义，不得编造精确发布时刻。

请求 `pageSize=100` 曾被规范为 50；必须按返回分页信息遍历、去重、核对总数。现有成功样本都在一页内，实盘多页仍待验证。固定查询窗口，发现翻页期间总量漂移/重复/缺页则重试或标记不完整。

不要复用曾返回 500 的猜测接口 `/api/disc/announcement/annList`，也不要将 `/disclosure/notice/company/index.html` 当成上市公司财报列表。

## 5. 采集流水线与更新频率

推荐流水线：需求清单 → 证券/组织身份 → 公告索引 → 全文归档 → 表格候选 → 校验/异常队列 → 版本事实入库 → 快照 S2 readiness → 因子与同池排名。

### 5.1 初始化只做一次，随后按事件增量

1. **需求计划。** 固化有限股票范围、cutoff、每只股票最新可用期间及 `required_s2_periods()` 结果，先读取已有事实与归档，只计划缺项或待更新项。
2. **公告索引。** 同一公司对所需最早披露至 cutoff 的全类别索引只扫描一次，由同一份索引服务多个报告期；定报分类负责快速定位全文，全类别负责发现更正、修订、撤回与补充。检索窗口须覆盖原报告发布到目标时点，不使用永久固定 730 天窗口。
3. **归档去重。** 保存请求、响应、页面、PDF 和收据；按内容哈希复用原始字节。索引中新出现/变化的公告才下载；同 URL 内容变化也保留新版本，不覆盖旧 PDF。
4. **提取缓存。** 按内容哈希、提取器版本、字段协议版本缓存。解析器改变才对受影响归档重算，不重复联网下载。
5. **更新检查。** 按来源和公司保存成功水位；每日检查新索引，建议以 7 个自然日重叠作为可配置起点，去重后仅处理增量。重叠不能保证捕获所有迟到回填，因此再周期性对仍在用报告做元数据核对和有条件内容复核。首期可按周安排，依据实际请求成本调整。
6. **恢复与失败隔离。** 公司—报告/索引任务具有持久状态；批次中断后从成功任务继续。失败进入有原因、有下一步的队列，不使其他股票失败，不自动循环全量重跑。

财报金额按季度/半年/年度披露及修订更新，**不需要每日重抓所有历史三表**。市值与行情按交易日刷新。沿用既有收盘后和盘前作业位置接入增量任务，不另建重复调度系统；北京时间判断交易日与 cutoffs，持久化时间携带时区。

### 5.2 访问纪律和成本

- 共用域名级限速器，包括多个进程/子 agent；巨潮保留现有约 2.5 秒请求间隔，深交所可从 3 秒、每域并发 1 起步，按真实限流反馈调整。
- 设置有限重试、指数退避、熔断及批次请求上限。403/429 或持续网络故障触发退避/备源，不靠提高并发解决。
- 保留 FetchGuard 的官方域名、端口、重定向和体积限制。透明代理伪 IP 只在核对当前本机配置后按进程显式声明，不把探针中某个 IP 或旧代理网段写进生产默认值。
- 先记录小批次的索引请求、下载数、缓存命中、耗时和模型用量，再据此估算扩池成本；本文不承诺未经实跑验证的全池完成小时数。

## 6. 正常样本自动准入，困难样本再交给模型和人工

### 6.1 各角色的职责

| 角色 | 承担的工作 | 不承担的工作 |
| --- | --- | --- |
| 普通程序 | 查询、下载、分页、归档、去重、已知版式提取、单位归一、规则核验、调度 | 猜测缺失数据或更改财务含义 |
| Luna 或实施方配置的模型 | 未知表格版式、扫描页、跨页续表、修订说明理解；输出结构化候选与原文定位 | 充当数据源、无原文估值、凭置信度决定正式准入、代签人工记录 |
| 人工 | 无法消除的口径歧义、两路径冲突、无法确认的修订关系 | 对每只股票每个金额重复点击确认 |

模型只接收必要财务页和说明页，输出金额、单位、期间、表名、行名、页码/坐标与证据文本。输出须按 schema 校验；`unknown` 是合法结果。按 PDF 哈希、页码、模型/提示词版本缓存，设置每报告调用上限；实际调用使用实施环境已配置的权限，不在代码或提示词中写入密钥，不为本方案购买新服务。

### 6.2 新增诚实的机器验证协议

现有 PDF 准入协议 v1/v2 强制 `HUMAN_VISUAL`、逐字段签署、固定证券/期间和前向模式。**主规格要求必要核验，并没有要求每个金额永远人工签字。** 实施方应新增有版本的机器验证证据协议并同步修改写入与读取，更新 ADR-015 的对应规则，保留旧人工协议兼容性。

新协议至少证明以下事项：

1. 官方索引与归档收据验证通过；证券、法律主体、报告期与全文类型一致，摘要未被当全文。
2. 合并表、归母/合并利润、累计值、币种单位与列期间明确；取值可定位到原始单元格。
3. 在实际出现的版式上完成代表性原文核验；正式批量使用时逐份核验标题/列头/单位/行名及版式约束。新增或漂移版式回到待验证，不能沿用宽松字符串命中直接升仓。
4. 独立校验路径核对关键值：可以采用原文中的同语义重复披露、独立表格定位/提取路径或可证明同口径的官方结构化数值；记录实际采用的方法与结果。不能把“同一提取函数跑两遍”或“PDF 在两站同哈希”伪装成数值独立验证。
5. 有关修订的索引窗口和处置完整，版本关系无未解决冲突；PIT 模式和可用时间依据可复核。

独立核对不要求每只股票固定下载两份来源。遇到舍入值只能在声明精度范围内做辅助核对，不以其替换原文精确数。无法达到所需核验条件的项进入异常队列，不反复让模型自证。

协议应保存校验器版本、规则结果、原文引用、证据哈希与真实执行时间；机器身份和人工身份分开。只接受受信的校验/升仓路径生成且能复核的证据，不以可随意编辑 JSON 中的 `verified=true` 放行。模型不能填写虚假的 `HUMAN_VISUAL` 或人类 `reviewer_id`。

### 6.3 更正和版本，不再每个期间重审同一公告

- 同一公司的全类别索引及公告处置结果按 ID/内容版本共享；五个期间可以引用同一证据，不重复扫描和人工处理五次。
- 标题关键字用于召回，不是最终结论。更正、修订、补充、差错更正及追溯调整必须结合正文，记录影响期间、字段和原公告关系。无关事项可由确定性规则或有证据的分类结果排除，歧义进入复核。
- “已完整核对窗口内未发现相关修订”是有效的有边界状态，不需要等待一个永远不会再更正的证明；不能写成“该公司从未修订”。将后续新公告作为增量事件处理。
- 原报告、修订全文、部分字段更正、撤回分别保留。后发报表的比较列可能是追溯调整值，不能回填成旧报告当时已经公开的原值。新版本只从其合法可用时点生效。
- 对修订全文，按整份报告版本准入。对仅更正部分字段的公告，建立明确关联原报告的有效版本包，保存每个字段的原始文档/单元格及承继关系；读写契约需显式支持这种组合，不能伪造共同 PDF 哈希，也不能任意跨源凑值。未支持或未核验的更正影响相关证券可用状态，不能悄悄忽略。
- 已发现影响必需字段的新版本但尚未验证时，相关新时点结果标记待更新；不能删掉新版本后又让旧版本冒充当前完整版本。更正前的历史时点仍按其当时可见版本读取。

直接复用真实反例验证：601012 的 2024 年报原版公告 `1223421477`（2025-04-30）、修订版 `1223477802` 与更正说明 `1223477804`（均为 2025-05-07）。更正说明在定报分类中缺席，在全类别检索可见；已有全类别证据为 267 条、9 页，说明位于第 7 页。该次更正改变主营业务同比表，五项 S2 金额不变。因此验收应检查原版/修订版身份随合法可用时点变化、旧版仍可回放及金额保持一致；不能谎称此例证明了五字段金额变化。金额发生变化的分支可用明确标注的离线用例补测。

## 7. 两种 PIT 模式分别实现

PIT 指“决策时点能否合法使用这一版本”。报告期末、公告时间、首次采集时间、校验完成时间和实际计算时间必须分开。

### 7.1 前向模式：最先交付的可用结果

`LIVE_OBSERVED` 保留真实 `first_seen_at`。可用时间不能早于来源公开、首次捕获、必要核验完成及线上特征准备就绪的相应时刻；再按既有快照/决策规则选择可用位置。只有公告日期时，使用主规格的公告日之后首个交易日盘前规则，并同时满足上述前向约束。

今天补采的多年财报，在核验后可以支持此后合法快照的当前 S2，只要计算依赖和版本链完整。不要因它过去未进入本系统，就永远禁止未来使用；也不要把今天的核验结果放进昨天已发布的前向决策。

金融事实、版本包、验证证据按事务入现有事实仓；市值使用与目标快照行情日匹配的已有归档。正式 readiness、策略能力状态和消费端都要识别通过验证的明确证券范围，不能仅将一个全局 `S2=true` 开关硬打开。

### 7.2 历史模式：有证据才能回放，不用“今天抓到”一概否定

主规格 §7.2 已允许 `HISTORICAL_RECONSTRUCTED`。保留今天的真实捕获时间，通过原始发布档案、原版内容/修订关系和保守时间规则另行重建历史 `available_at`。只有当前修订版、无原版/发布时间依据的记录，不能用于相关历史时点。

已发现的实现差距：

- `operations/s2_readiness.py` 当前无条件要求 `first_seen_at <= cutoff`，会排除合法历史重建。
- `domain/fundamentals/fact_repository.py` 的现有已审阅 PDF 协议仅支持 `OBSERVED/LIVE_OBSERVED`。
- 领域 PIT 已有模式结构，但不代表 PDF 生产准入和 S2 读取已经贯通。

实施时为历史重建新增明确证据和模式分支，更新生产升仓、事实仓读取与 readiness；前向分支保留首见约束，不能全局删掉时间检查。记录 `available_basis=RECONSTRUCTED` 等现有对应枚举、依据版本、历史 cutoff、今天的计算时间和配方。

历史 S2 还需要对应历史行情日的市值、证券池/行业有效期和交易日历。只有财报历史不等于完整历史 S2。历史日历使用已验证支持的年份，不能用仅覆盖当前年度的日历推算所有年份。先选档案证据齐全的有限区间验收，不要求本轮补齐全 A 股全部历史。

## 9. 三个工作包及退出标准

### A. 从官方原文到可用的前向 S2

把深交所成功探针接为适配器；建立动态期间需求、共享公司索引、自动核验证据和正式升仓/读取契约；用原有八股固定范围打通匹配快照的完整 S2。300502 用于额外版式验证，不能拿单份半年报冒充已完成该股全部期间。

退出标准：

- 至少一次受控真实 CLI 运行从索引发现、下载归档、提取、验证到入库/正式读取完成，明确来源、cutoff 和运行证据；旧归档可复用，但报告真实区分缓存与新采。
- 固定八股每只都有结果。具备完整合格输入者给出 F07—F10、因子依赖和同池排名；非正分母等合法排除独立列出；资料/验证缺口不能伪装成策略排除。
- 既有产品研究/能力入口能够消费正式结果，正确显示已验证范围；仅生成 CLI 候选文件不算完成。S1 对照使用同一有效证券池，并说明与原 S1 池的差别。
- 不要求八股全都产生信号，不要求全市场 95% 才允许这个有限范围运行；未完成的范围仍显示缺口，不冒称全池 S2 已可用。

### B. 扩展覆盖并形成日常可恢复运行

在 A 的同一条链路上，对配置池进行一次有限初始化。制造业先扩展，其他非金融按版式/口径适用性扩展；金融明确排除。完成增量水位、归档/解析缓存、失败隔离、异常队列和运行覆盖报告，接入既有调度。

退出标准：

- 当前配置中每只股票均有状态与原因，所有计数之和等于冻结目标池；报告正式可用、数据不足、待核验、来源失败、模板不支持和业务规则排除，区分数量与字段分母。
- 重跑不重复写事实和下载已核实不变的 PDF；中断可恢复；一个来源失败可在有证据的条件下切换备源，失败不污染其他证券。
- 新报告/修订只更新受影响证券及派生结果；记录实跑请求/下载/模型调用/耗时。每个批次只做有限重试，剩余缺口给出具体下一步，不能无限循环探针。
- 对已合格范围完成一次增量执行证据。全池有可解释状态不等于全池公式可算，交付报告必须同时展示实际可算范围。

### C. 在可证明范围内支持历史重建

按 §7.2 实现独立的历史准入与读取，使用有原版发布档案、修订证据及对应市值/证券池资料的有限区间进行回放。不为补历史而停用已完成的前向范围。

退出标准：

- 一组可重放样本保留今天首见时间，又能依据历史公开证据在正确 cutoff 读取；未来版本与未知依据被拒绝。
- 有真实修订样本则验证修订前后差异；若所选真实窗口无修订，诚实报告窗口结论，另用等价离线用例验证分支，不能编造一次线上修订成功。
- 历史财报、市值或池定义缺失时明确标出可回放边界；不能用今天市值补历史，也不能将有限区间结论扩展到全历史。

每包完成后记录可复现命令与证据并关闭已满足范围，后包复用已有验收。新发现只有阻断上述结果、事实正确性或数据完整性的缺陷才纳入本次实现，其他改善进入已有待办。

## 10. 验证计划：集中且与变更对应

不在每次编辑后跑全套测试。优先用已归档样本作离线回归，每个完整工作包集中跑受影响测试；适用仓库门禁按原规定执行。真实网络只验证新增来源与最终闭环，失败有限重试，不反复全池采集当测试。

重点复用现有测试：`test_collect_s2_cninfo_batch.py`、`test_cninfo_report_index.py`、`test_cninfo_financial_candidate.py`、`test_pdf_promotion.py`、`test_fact_repository.py`、`test_s2_readiness.py`、`test_s2_required_periods.py`、`test_s2_formula_engine.py`，以及受影响的 PIT/API 测试。新增用例只覆盖新行为或确切缺陷。

必要场景：

- 正常全文和混入摘要/错公司/错期间；元与千元、母公司与合并、累计与单季；缺失不能变零。
- 季报、半年报、年报的动态需求；未知版式不自动套已知模板。
- 索引分页截断、重复/漂移、下载损坏、限流、主源失败与恢复；真实多页未跑过时标记仅离线验证。
- 同时点原版/修订版选择；已发现但未验证的新版本不让旧值静默复活；同源/跨源相同字节不重复入库。
- 机器证据可复核、伪造标志不放行、旧人工协议仍可读；原子失败无半份财报写入。
- 前向模式不偷用晚到事实；历史模式不因今天首见而全盘拒绝，也不接受无原始档案的历史声明；市值错日拒绝。

数据任务以 CLI/API 和归档证据为主，不要求桌面浏览器验证；未验证的界面、部署或长期稳定性单独注明。不要启动受当前桌面隔离规则限制的浏览器路径。
